# 11.4 — Lab: Effect Editor

**Iteración 11.4 de la Fase 11.** Arquitectura funcional de la herramienta principal para **crear,
modificar, inspeccionar, validar y mantener** cualquier efecto del juego (ataques, habilidades, objetos,
herramientas, estadios, energías especiales, efectos internos). Se monta en el **host del Workspace
(R3)** del Shell (11.1) y se integra con la Galería (11.2) y el Animation Editor (11.3) por **identidad
de recurso** (ID estable). Ensamblado EXCLUSIVAMENTE con ComponentStyle existentes. Cadena congelada
`Component → ComponentStyle → Visual Tokens → Theme`.

> **Regla de Oro (intacta).** El editor **no crea un motor de efectos**, **no ejecuta lógica
> alternativa** y **no simula**. Construye y modifica la **definición** del efecto (datos); el **motor
> compartido** la ejecuta después. El Preview de ejecución usa **exactamente el mismo motor** que el
> juego. No existe "preview simplificado". El editor **solo modifica datos**: nunca el motor, el
> renderer ni el sistema de animaciones.

---

## Finalidad
Definir la lógica completa de una acción del juego como una **secuencia de acciones encadenadas**,
ejecutarla con el motor real, inspeccionar el estado antes/después, validarla y mantener sus referencias
—sin duplicar lógica ni motor.

## Responsabilidades
- **Ciclo de vida del recurso:** abrir/crear/duplicar/renombrar/guardar/guardar como/descartar/restaurar.
- **Componer la estructura lógica:** organizar, reordenar, agrupar, activar/desactivar y copiar/pegar
  acciones, con **deshacer/rehacer**.
- **Ejecutar** el efecto con el motor real, reiniciar y **inspeccionar estado antes/después**.
- **Validar** (errores/advertencias) y mantener **referencias cruzadas** y **animaciones asociadas**.
- **Comparar** actual↔guardado y **restaurar**.

## Layout (regiones del Lab dentro de R3)
```
┌──────────────────────────────────────────────────────────────────────┐
│ LabBar (Toolbar): nuevo·abrir·duplicar·guardar·guardar como·descartar │
│                   ↶ deshacer ↷ rehacer · validar · ▶ ejecutar ↺ · comparar│
├──────────────┬──────────────────────────────┬────────────────────────┤
│ A · Explorador│ B · Flujo del efecto         │ D · Inspector          │
│   de acciones │   (acciones encadenadas,     │  Propiedades (acción)  │
│  (catálogo de │    grupos y condiciones,     │  Metadatos             │
│   tipos a     │    vista estructurada)       │  Validación            │
│   insertar)   │  · aplicar daño        ⦿    │  Historial (sesión)    │
│  búsqueda     │  · si (condición)      ⦿    │  Refs cruzadas         │
│  categorías   │     └ robar cartas     ⦿    │  Animaciones asociadas │
│  (arrastrar → │  · ejecutar animación  ○    │  Recursos utilizados   │
│   al flujo)   ├──────────────────────────────┤                        │
│               │ C · Preview de ejecución     │                        │
│               │   (motor real) estado ⟶      │                        │
│               │   [ ▶ ejecutar ↺ · antes|después ]                    │
├──────────────┴──────────────────────────────┴────────────────────────┤
│ (Status Bar del Shell: sin guardar · validación · ejecución · progreso)│
└──────────────────────────────────────────────────────────────────────┘
```
Splitters entre A/B/D y B/C: `DividerStyle` + `ResizeHandleStyle`.

## Regiones y composición (todo con ComponentStyle existentes)
- **LabBar** — `ToolbarStyle`. Operaciones de fichero (`ButtonStyle`/`MenuStyle`), deshacer/rehacer
  (`IconButtonStyle`), validar (`ButtonStyle`), ejecutar/reiniciar (`IconButtonStyle`), conmutador de
  comparación (`ToggleButtonStyle`), indicador "sin guardar" (`BadgeStyle`).
- **A · Explorador de acciones (catálogo de tipos)** — `PanelStyle` con `SearchFieldStyle` +
  `TreeStyle`/`ListViewStyle` (tipos de acción por categoría) + `ChipStyle` (filtros). Insertar en el
  flujo por arrastre (`DropTargetStyle`) o comando. *(No se diseñan las acciones; solo su contenedor.)*
- **B · Flujo del efecto (superficie editable protagonista)** — la **estructura lógica** como
  **secuencia jerárquica** (tipo esquema/AST), NO un grafo de nodos: `TreeStyle`/`TreeRowStyle` donde el
  orden vertical = encadenamiento, la anidación = grupos/condiciones, y las guías de jerarquía usan
  hairlines (`DividerStyle`).
  - **Reordenar / agrupar:** `DropTargetStyle` + selección `DataRowStyle`, rol `Continuity`.
  - **Habilitar/deshabilitar:** `SwitchStyle`/`CheckboxStyle` por acción.
  - **Copiar/pegar/duplicar/eliminar/agrupar:** `ContextMenuStyle`/`MenuStyle`.
  - **Estado por acción** (válida/advertencia/error/deshabilitada): `BadgeStyle.Tone`.
- **C · Preview de ejecución (Z6)** — `PreviewStyle` que **monta el motor real** ejecutando el efecto;
  controles `IconButtonStyle` (ejecutar/reiniciar/paso). **Estado antes/después:** dos vistas de estado
  (`PropertyGroupStyle`/`TableStyle`/`TreeStyle`) separadas por `DividerStyle`, con diferencias marcadas
  por `BadgeStyle.Tone`. Cuando una acción ejecuta una animación, el Preview muestra el **render real**
  (mismo sistema del 11.3).
- **D · Inspector (Z7)** — `InspectorSectionStyle` + `PropertyGroupStyle` + `PropertyRowStyle`:
  - *Propiedades / parámetros* de la acción seleccionada, editables en línea (`InlineEditFieldStyle`) y
    por tipo (`SliderStyle`, `SegmentedButton`/`MenuStyle`, `CheckboxStyle`/`SwitchStyle`, `ChipStyle`).
  - *Metadatos / renombrar:* `PropertyRow` + `InlineEditFieldStyle`.
  - *Validación:* `BadgeStyle.Tone` + `PropertyRow` en estado `Error`.
  - *Historial de sesión* (deshacer/rehacer): `ListViewStyle`/`ListRowStyle` + `IconButtonStyle`.
  - *Referencias cruzadas* (cartas/otros efectos que lo usan): `ListViewStyle` + `ButtonStyle` `Ghost`.
  - *Animaciones asociadas:* `ListViewStyle`/`ListRowStyle` + `ButtonStyle` `Ghost` (abre en Galería/
    Editor por ID estable).
  - *Recursos utilizados:* `TreeStyle`/`ListViewStyle`.

## Jerarquía visual
Flujo del efecto (materia editable, protagonista) + Preview de ejecución (verdad del motor) › Explorador
de acciones (insumo) › Inspector (mando) › LabBar/Status (control/residual). El chasis reposa; solo
selección/foco/edición/alerta suben (VG-K).

## Flujo principal
1. **Abrir** un efecto (desde una carta, la búsqueda o el Command Palette) o crear/duplicar.
2. **Componer:** arrastrar tipos desde A al flujo B; anidar/agrupar; ordenar; ajustar parámetros en D.
3. **Ejecutar:** C corre el efecto con el motor real; inspeccionar estado antes/después.
4. **Validar:** LabBar → resultados en D + Status Bar + `Toast`.
5. **Guardar:** persiste; se limpia "sin guardar"; las referencias reflejan el cambio (mismo ID).

## Flujos secundarios
- **Deshacer/rehacer** sobre el modelo de datos; historial navegable en D.
- **Comparar actual↔guardado:** modo dividido; diferencias de acciones con `BadgeStyle.Tone` en B.
  **Restaurar guardado:** `ConfirmationDialogStyle`.
- **Guardar como / renombrar / descartar:** `DialogStyle` / `ConfirmationDialogStyle`.
- **Copiar/pegar acciones** entre posiciones, grupos o efectos abiertos.

## Integración explícita con los Labs de animación
Cuando una acción del efecto referencia una animación (p. ej. "ejecutar animación"):
- **Navegación entre Labs:** la sección *Animaciones asociadas* (D) muestra la animación con un enlace
  `ButtonStyle` `Ghost`; activarlo pide al **Shell** conmutar al Lab destino —**Animation Gallery**
  (inspeccionar/comparar) o **Animation Editor** (editar)— montando esa animación.
- **Conservación del contexto:** el estado del Effect Editor se **preserva en la sesión** del Shell; al
  volver (ruta de contexto / historial), el efecto reaparece intacto, incluida la acción seleccionada.
- **ID estable:** el efecto almacena la **referencia por ID** de la animación (11.2), nunca una copia.
  El mismo ID identifica el recurso en Galería, Editor y este efecto.
- **Sin duplicación:** una sola animación-recurso, referenciada por ID desde múltiples efectos; editarla
  en el Animation Editor la actualiza en **todos** los que la referencian (fuente única). El efecto
  nunca embebe datos de animación.

## Navegación
- Integración por identidad de recurso; abrir/guardar operan sobre el mismo efecto (ID estable).
- Conmutar entre Labs = cambio de Lab del Shell (estado preservado en sesión).
- Referencias cruzadas y animaciones asociadas → otros Labs vía contrato del host.

## Estados
- **rest / hover / pressed / selected:** acciones (`DataRowStyle`), controles.
- **editing:** parámetro en edición = `Focused` de `InlineEditFieldStyle`.
- **dirty (sin guardar):** `BadgeStyle` en LabBar + punto en pestaña (`TabStyle`); cerrar con cambios →
  `BlockingOverlayStyle`/`ConfirmationDialogStyle`.
- **loading:** `SkeletonStyle`/`BusyOverlayStyle` al abrir.
- **executing / operación larga:** `ProgressOverlayStyle`/`BusyOverlayStyle` + segmento de Status Bar.
- **empty:** sin efecto abierto → `EmptyStateStyle` ("Abrir / Crear nuevo").
- **error:** validación con errores/advertencias (`BadgeStyle.Tone` + `PropertyRow` Error); recurso
  inexistente → `EmptyState` error + `Toast`; fallo crítico → nivel del Shell.
- **compare:** modo dividido activo.

## Accesibilidad
- Anillo de foco único; orden de foco = orden visual (LabBar → A → B → C → D).
- Estado nunca solo por color (acción deshabilitada con icono/etiqueta; validación con texto; "sin
  guardar" con marca textual; diferencias con etiqueta además de tono).
- Áreas de toque adecuadas (Android); overlays descartables; contraste reservado; el flujo jerárquico
  expone nivel/estado de expansión.

## Comportamiento con teclado
- Command Palette (Shell) para comandos e ir a un efecto/animación por ID.
- Fichero: guardar / guardar como / nuevo / duplicar por atajo.
- Edición: deshacer / rehacer; copiar / pegar / duplicar / eliminar / agrupar acción; mover ↑/↓
  (reordenar por teclado); activar/desactivar; expandir/colapsar grupos (←/→).
- Ejecución: ejecutar / reiniciar / paso por atajo.
- `Esc` cierra overlays / cancela edición. Acciones por teclado **no se animan** (Motion canon).

## Reglas de composición
- El editor **modifica datos**; el motor los ejecuta; el Preview **monta el motor real** (Regla de Oro).
- El **flujo del efecto** se representa como **secuencia jerárquica** (Tree + indentación + hairlines),
  no como grafo de nodos: legibilidad sobre decoración; sin componente "conector/arista".
- Cada región consume su ComponentStyle; ninguna lee Visual Tokens directamente.
- Reordenar/agrupar = `DropTargetStyle`; estado antes/después y comparación = paneles de estado +
  `DividerStyle`. Todas son **composiciones**, no componentes nuevos.
- Relación con Galería/Editor por **ID estable**; ningún Lab modifica a otro ni al Shell.

## Restricciones
- Sin explorador de archivos: se abre por **Recurso/ID** (Especialización §2).
- El editor no valida ni ejecuta "a su manera": usa las **reglas y el motor del núcleo compartido**.
- No modifica motor, renderer ni sistema de animaciones.
- Sin componentes/tokens/principios/estilos/sistemas nuevos.

## Cierre
**Iteración 11.4 — CERRADA.** El Effect Editor puede implementarse **íntegramente** con el Design System
existente.

### Por qué completa el ecosistema de creación/edición/validación/ejecución sobre un único motor
Los cuatro Labs forman un ecosistema cerrado y coherente sobre **un solo motor compartido**:
- **Boot + Shell (11.1)** — el contenedor permanente, el estado global y la sesión que preserva el
  contexto al saltar entre Labs.
- **Animation Gallery (11.2)** — descubrir, reproducir, inspeccionar, comparar y validar animaciones a
  escala, con **identidad estable** y base de conocimiento de referencias.
- **Animation Editor (11.3)** — crear/editar/validar animaciones editando **datos** que ejecuta el
  renderer real.
- **Effect Editor (11.4)** — crear/editar/validar/**ejecutar** la lógica del juego editando **datos**
  que ejecuta el **motor real**, y que **referencian** animaciones por ID sin duplicarlas.

El vínculo clave es la **identidad de recurso (ID estable)**: un efecto referencia animaciones que se
descubren en la Galería y se editan en el Animation Editor, todo apuntando al **mismo recurso** y al
**mismo motor**. Así, todo el ciclo —definir la lógica, ejecutarla como en el juego, verla animada,
validarla, rastrear sus usos y compararla— queda cubierto **sin un solo componente, token o principio
nuevo**, con **cero duplicación** de lógica, motor, renderer o animación. Es la confirmación definitiva
de que el Design System basta para las herramientas más complejas del Studio y de que la Arquitectura
Dual + Regla de Oro se sostienen de extremo a extremo.
