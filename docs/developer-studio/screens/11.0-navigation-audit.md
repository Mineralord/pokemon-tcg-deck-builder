# 11.0 — Auditoría arquitectónica de navegación (corrección de propósito)

**No modifica el canon.** Detecta y corrige, dentro de la Fase 11 (abierta), los puntos que asumieron
erróneamente que el Studio era un **IDE / gestor multi-proyecto / herramienta multi-desarrollador**.
Base: `PRINCIPIO-ESPECIALIZACION-ABSOLUTA` (§2 exclusiones), 4 Pilares (Desarrollo Unipersonal +
Especialización Absoluta), `SPATIAL-ARCHITECTURE` (Shell único con Labs).

## Contexto confirmado (nuevo, pero coherente con el canon)
- **Un solo desarrollador**; Claude Code implementa. **Un único proyecto**: Pokémon TCG Clone.
- Propósito nuclear reafirmado: **galería perfecta de TODAS las animaciones**, cada una
  localizable · reproducible · inspeccionable · editable · comparable · testeable · validable, con el
  **mismo motor** que el juego (Regla de Oro I1; Benchmark Z10; Especialización §3.2).
- **Target Android** (juego y Studio). No web. No IDE genérico. No múltiples proyectos.

---

## Auditoría elemento por elemento

### 1. Launcher (11.1)
1. **¿Sigue teniendo sentido?** No como lo diseñé. Mi 11.1 lo planteó como *selector de herramientas/
   superficies + recientes de proyectos*: eso importa el modelo multi-tool/multi-proyecto que el canon
   rechaza (§2 "❌ Abrir proyectos").
2. **¿Mantener?** No en esa forma.
3. **¿Simplificar?** Sí, hasta casi desaparecer. Un Studio unipersonal de proyecto único **arranca
   directo** en su superficie de trabajo. A lo sumo queda un **arranque/boot** instantáneo (splash con
   estado de carga vía `LoadingPlaceholder`/`Skeleton`), sin decisiones.
4. **¿Eliminar?** Se elimina el *concepto* "Launcher = elegir herramienta/proyecto". Se conserva solo
   un boot sin interacción. **Justificación:** P11 (latencia), P4 (solo lo que aporta); ninguna elección
   real que ofrecer con un único proyecto y un único destino.

### 2. Project Selector (11.2)
1. **¿Sentido?** No. Elegir/abrir proyecto es exactamente la exclusión canónica §2.
2. **¿Mantener?** No.
3. **¿Simplificar?** No aplica.
4. **¿Eliminar?** **Sí — ERROR DE ARQUITECTURA detectado y corregido.** Requiere el componente/capacidad
   "abrir proyecto", inexistente y **prohibido** por canon. Se elimina de la Fase 11. **Justificación:**
   §2, §3 (prueba de pertenencia: no sirve a un proyecto único).

### 3. Project Dashboard (11.3)
1. **¿Sentido?** No como panel de gestión de proyecto(s). Un dashboard de métricas/estado de proyecto es
   patrón de IDE/gestor; con un único proyecto es redundante frente a la navegación Lab-céntrica.
2. **¿Mantener?** No como "dashboard de proyecto".
3. **¿Simplificar?** Sí. Si algo de valor sobrevive, es un **Home = Lab por defecto** (la Galería de
   Animaciones), no una capa de dashboard aparte.
4. **¿Eliminar?** Se elimina el concepto "Dashboard". Su único residuo útil (entrar y ver el estado del
   trabajo) lo absorbe la **Galería de Animaciones** como Lab inicial. **Justificación:** P4, P10 (menos
   ruido); el estado se ve *trabajando*, no en un tablero separado.

### 4. Workspace principal (11.4)
1. **¿Sentido?** **Sí, plenamente.** Es el **Shell** canónico (Z1–Z12): la única superficie persistente
   del Studio, cuyo contenido cambia según el **Lab activo** (P9/P12).
2. **¿Mantener?** **Sí.** Es el corazón; no se toca su razón de ser.
3. **¿Simplificar?** Reframe, no simplificación: deja de ser "una pantalla entre varias" y pasa a ser
   **la** superficie. Las "pantallas" 5–12 son **Labs dentro** de este Shell, no destinos separados.
4. **¿Eliminar?** No. **Justificación:** `SPATIAL-ARCHITECTURE` Z5 + P9; es canon.

### 5. Navegación principal
1. **¿Sentido?** El modelo que insinuaba mi lista (Launcher → Selector → Dashboard → pantallas) es de
   **IDE**. No tiene sentido.
2. **¿Mantener?** No el modelo IDE.
3. **¿Simplificar?** Sí: **conmutación de Labs dentro de un Shell único**, más Command Palette (Z4) y
   Biblioteca (Z3). Sin jerarquía de proyecto.
4. **¿Eliminar?** Se elimina la navegación tipo "abrir proyecto → dashboard → subpantallas".
   **Justificación:** Especialización §2/§3; SPATIAL Z3/Z4/Z5.

### 6. Flujo de apertura
1. **¿Sentido?** El flujo "arranque → elegir proyecto → dashboard → workspace" no tiene sentido.
2. **¿Mantener?** No.
3. **¿Simplificar?** Sí: **arranque → Shell con el Lab por defecto (Galería de Animaciones)**. Cero
   pasos de selección.
4. **¿Eliminar?** Se eliminan los pasos intermedios. **Justificación:** P11 (latencia), Desarrollo
   Unipersonal (sin fricción de gestión).

## Nueva arquitectura de navegación (solo navegación; sin diseñar pantallas)

**Principio rector:** *un solo desarrollador, un solo proyecto, una sola superficie persistente (el
Shell), muchos Labs especializados.* La navegación NO es entre "pantallas/proyectos", sino entre
**Labs** dentro del mismo Shell (P9: las zonas no se mueven; cambia el contenido).

### Topología
```
[ Boot ]  (arranque instantáneo, sin decisiones)
   │
   ▼
┌──────────────────────────────────────────────────────────────┐
│  STUDIO SHELL  (única superficie persistente, P9)            │
│                                                              │
│  Z1 Barra global (identidad · ruta Lab›Recurso›Variante)     │
│  Z2 Riel/Selector de Labs  ◄── navegación principal          │
│  Z3 Biblioteca (Resources del Lab activo)                    │
│  Z4 Command Palette (acceso universal por teclado)           │
│  Z5 Workspace / Z6 Preview / Z7 Inspector / Z9 Timeline /    │
│     Z10 Benchmark  ── se reconfiguran según el Lab           │
│  StatusBar (estado de motor/validación)                      │
└──────────────────────────────────────────────────────────────┘
```

### Labs (destinos de la navegación principal, Z2) — orden por frecuencia real
1. **Galería de Animaciones** *(Lab por defecto y protagonista)* — catálogo completo de TODAS las
   animaciones; localizar · reproducir · inspeccionar · editar · comparar · probar · validar con el
   motor del juego (Benchmark Z10 + Preview Z6 + Timeline Z9 + Inspector Z7).
2. **Galería de Cartas** — navegación Resource-céntrica de cartas (Biblioteca Z3 + Preview Z6).
3. **Editor de Cartas** — no es destino aparte: es el **drill-in** de la Galería de Cartas (misma
   navegación, Inspector Z7 en modo edición).
4. **Editor de Efectos** — Lab del DSL de efectos, ligado a la carta/animación seleccionada.
5. **Editor de Combate (Rules/Battlefield Lab)** — Workspace Z5 como tablero editable.
6. **Deck Sandbox** — probar mazos con el motor real.
7. **Build** — empaquetar/validar el proyecto (Android).
8. **Configuración** — ajustes globales del Studio (no de proyecto).

### Reglas de navegación
- **Sin apertura de proyecto, sin selector, sin dashboard, sin recientes de proyecto.**
- La navegación primaria es **conmutar de Lab** (Z2); la secundaria es **seleccionar Resource** en la
  Biblioteca (Z3); la terciaria es **Command Palette** (Z4, teclado).
- El **Shell es único y persistente**: las zonas mantienen su sitio entre Labs (P9); solo cambia el
  contenido. Editar es un **modo del Lab** (Inspector en edición), no otra pantalla.
- Ruta de contexto = `Lab › Recurso › Variante` (breadcrumb conceptual en Z1), nunca `Proyecto › …`.
- Un Lab candidato futuro debe pasar la **prueba de pertenencia** (§3) antes de aparecer en Z2.

### Impacto en el plan de la Fase 11 (corrección, no reescritura del canon)
- **Eliminadas:** Project Selector, Project Dashboard (conceptos IDE/multi-proyecto).
- **Reconvertido:** Launcher → *Boot* mínimo sin decisiones (o inexistente como pantalla propia).
- **Reencuadrado:** "Workspace principal" = **Shell** (no una pantalla entre varias); las demás
  "pantallas" son **Labs dentro** del Shell.
- **Nuevo orden de iteraciones** (superficie única + Labs): Shell → Galería de Animaciones → Galería de
  Cartas → Editor de Cartas → Editor de Efectos → Editor de Combate → Deck Sandbox → Build → Config.
