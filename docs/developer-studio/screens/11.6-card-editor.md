# 11.6 — Lab: Card Editor

**Iteración 11.6 de la Fase 11.** Arquitectura funcional de la herramienta oficial para **crear,
modificar, validar y mantener** cualquier carta del proyecto. Se monta en el **host del Workspace (R3)**
del Shell (11.1) y trabaja sobre **el mismo recurso** descubierto en la Card Gallery (11.5). Ensamblado
EXCLUSIVAMENTE con ComponentStyle existentes. Cadena congelada
`Component → ComponentStyle → Visual Tokens → Theme`.

> **Qué NO es.** No es un editor gráfico, de imágenes ni de texto; no pertenece al juego. Es una
> herramienta exclusiva del Studio (APK 2).
>
> **Regla fundamental.** El Card Editor **modifica exclusivamente el recurso "Card"**. Nunca modifica
> animaciones, efectos, sonidos, partículas, layouts, renderer ni motor: solo **administra referencias
> por ID estable**. Ejemplo — el ataque *Solar Beam* referencia `effect.attack.solarbeam`,
> `animation.attack.solarbeam`, `sound.attack.solarbeam`; la carta **nunca contiene una copia** de esos
> recursos.
>
> **Identidad estable.** Abrir una carta edita **el mismo recurso** por su ID; no se crea copia ni
> cambia la identidad. *(Duplicar es una acción explícita que crea un **nuevo** recurso-carta con **nuevo**
> ID, conservando sus referencias por ID; nunca copia los recursos referenciados.)*
>
> **Regla de Oro.** El Preview usa **el renderer oficial compartido**; se ve exactamente igual que en el
> juego. Nunca un renderer alternativo.

---

## Finalidad
Definir por completo los **datos** de una carta —metadatos, estadísticas, ataques, habilidades, reglas,
debilidades/resistencias/retirada, legalidad, expansión/numeración/rareza, ilustrador, idioma, estado,
notas— y sus **referencias** a efectos/animaciones/sonidos, viéndola con el render oficial, de forma
reversible y validada.

## Responsabilidades
- **Ciclo de vida del recurso Card:** abrir/crear/duplicar-como-nuevo/renombrar/guardar/guardar como/
  descartar/restaurar.
- **Editar los datos propios** de la carta (todo lo anterior), con **deshacer/rehacer**.
- **Administrar referencias por ID** a efectos, animaciones y sonidos (fijar/cambiar/limpiar), sin
  copiarlos.
- **Validar** (errores/advertencias con las reglas del núcleo) y mantener **referencias cruzadas** y
  **recursos asociados**.
- **Comparar** actual↔guardado y **restaurar**; renderizar con el **renderer oficial**.

## Layout (regiones del Lab dentro de R3)
```
┌──────────────────────────────────────────────────────────────────────┐
│ LabBar (Toolbar): nuevo·abrir·duplicar↦nuevo·guardar·guardar como·descartar│
│                   ↶ deshacer ↷ rehacer · validar · comparar           │
├───────────────┬───────────────────────────────────┬──────────────────┤
│ A · Estructura│ B · Preview oficial (render real)  │ D · Inspector    │
│   de la carta │   (comparar: actual | guardado)    │  Propiedades     │
│  · Identidad  │                                    │  Metadatos       │
│  · Metadatos  │                                    │  Validación      │
│  · Estadíst.  │                                    │  Historial (ses.)│
│  · Ataques[]  │                                    │  Recursos asoc.  │
│  · Habilid.[] │                                    │   effect/anim/snd│
│  · Reglas     │                                    │   (refs por ID ⇄)│
│  · Deb/Res/Ret│                                    │  Refs cruzadas   │
│  · Legalidad  │                                    │                  │
├───────────────┴───────────────────────────────────┴──────────────────┤

└──────────────────────────────────────────────────────────────────────┘
```
Splitters A/B/D: `DividerStyle` + `ResizeHandleStyle`.

## Regiones y composición (todo con ComponentStyle existentes)
- **LabBar** — `ToolbarStyle`. Operaciones de fichero (`ButtonStyle`/`MenuStyle`; "duplicar como nuevo"
  crea un recurso con nuevo ID), deshacer/rehacer (`IconButtonStyle`), validar (`ButtonStyle`),
  comparación (`ToggleButtonStyle`), indicador "sin guardar" (`BadgeStyle`).
- **A · Estructura de la carta** — `PanelStyle` con la carta como **esquema jerárquico**
  (`TreeStyle`/`TreeRowStyle`): secciones (Identidad, Metadatos, Estadísticas, Ataques[], Habilidades[],
  Reglas, Debilidad/Resistencia/Retirada, Legalidad). Seleccionar una parte la abre en el Inspector.
  - **Ataques/Habilidades** son listas: reordenar con `DropTargetStyle` (rol `Continuity`); añadir/
    eliminar/duplicar/copiar/pegar con `ContextMenuStyle`/`MenuStyle`; estado de validación por fila con
    `BadgeStyle.Tone`.
- **B · Preview oficial (Z6)** — `PreviewStyle` que **monta el renderer oficial de carta** del núcleo;
  encuadre/zoom en `PreviewOverlayStyle`. **Comparar actual↔guardado:** división con `DividerStyle` +
  `SelectionFrameStyle`.
- **D · Inspector (Z7)** — `InspectorSectionStyle` + `PropertyGroupStyle` + `PropertyRowStyle`:
  - *Propiedades / metadatos:* todos los campos editables en línea (`InlineEditFieldStyle`) y por tipo
    (`SliderStyle` numéricos como estadísticas/coste de retirada; `SegmentedButton`/`MenuStyle` para
    rareza/tipo/subtipo/regulación/idioma/estado; `CheckboxStyle`/`SwitchStyle` para legalidad;
    `ChipStyle` para etiquetas).
  - *Recursos asociados (referencias por ID):* por cada ataque/habilidad, filas `PropertyRow` con
    **Effect ID / Animation ID / Sound ID** y enlace `ButtonStyle` `Ghost` para navegar. **Fijar/cambiar
    referencia** = selector compuesto (`PopoverStyle`/`MenuStyle` + `SearchFieldStyle` + `ListViewStyle`
    de recursos existentes); elegir **asigna el ID**, nunca copia el recurso.
  - *Validación:* `BadgeStyle.Tone` + `PropertyRow` en estado `Error`.
  - *Historial de sesión* (deshacer/rehacer): `ListViewStyle`/`ListRowStyle` + `IconButtonStyle`.
  - *Referencias cruzadas* (dónde se usa la carta: mazos, escenarios de combate): `ListViewStyle` +
    `ButtonStyle` `Ghost`.

## Jerarquía visual
Preview oficial (verdad del render) + Estructura de la carta (materia editable) › Inspector (mando) ›
LabBar/Status (control/residual). El chasis reposa; solo selección/foco/edición/alerta suben (VG-K).

## Flujo principal
1. **Abrir** desde la Card Gallery (mismo recurso/ID) o **crear**/duplicar-como-nuevo.
2. **Editar:** seleccionar una parte en A → editar sus campos en D; ajustar ataques/habilidades;
   administrar sus referencias (Effect/Animation/Sound ID) con el selector.
3. **Ver en vivo:** B renderiza con el renderer oficial (idéntico al juego).
4. **Validar:** LabBar → resultados en D + Status Bar + `Toast`.
5. **Guardar:** persiste sobre el mismo recurso; se limpia "sin guardar"; la Card Gallery lo refleja.

## Flujos secundarios
- **Deshacer/rehacer** sobre el modelo; historial navegable en D.
- **Comparar actual↔guardado:** modo dividido en B; diferencias por `BadgeStyle.Tone` en A.
  **Restaurar guardado:** `ConfirmationDialogStyle`.
- **Guardar como / duplicar-como-nuevo / renombrar / descartar:** `DialogStyle` / `ConfirmationDialogStyle`.
- **Copiar/pegar** partes (ataque/habilidad) entre cartas abiertas (los datos propios se copian; las
  referencias se copian **como IDs**, no como recursos).

## Navegación por ID estable
- **Card Gallery:** abrir/guardar sobre el mismo recurso-carta (ID); volver a la Galería para descubrir.
- **Animation Gallery / Animation Editor:** desde una referencia de animación → inspeccionar/editar la
  animación en su Lab (por ID); el estado del Card Editor se **preserva en sesión**.
- **Effect Editor:** desde una referencia de efecto → editar el efecto (por ID) en su Lab.
- Todo por **contrato del host** del Shell; sin duplicar información; sin que un Lab modifique a otro.

## Estados
- **rest / hover / pressed / selected:** partes (`DataRowStyle`), controles.
- **editing:** campo en edición = `Focused` de `InlineEditFieldStyle`.
- **dirty (sin guardar):** `BadgeStyle` en LabBar + punto en pestaña (`TabStyle`); cerrar con cambios →
  `BlockingOverlayStyle`/`ConfirmationDialogStyle`.
- **loading:** `SkeletonStyle`/`BusyOverlayStyle`; **validación/operación larga:** `ProgressOverlayStyle`
  + segmento de Status Bar.
- **empty:** sin carta abierta → `EmptyStateStyle` ("Abrir desde la Card Gallery / Crear nueva").
- **error:** validación (`BadgeStyle.Tone` + `PropertyRow` Error); referencia rota (ID inexistente) →
  `PropertyRow` Error + `ToastStyle`; recurso inexistente → `EmptyState` error; crítico → nivel del Shell.
- **compare:** modo dividido activo.

## Accesibilidad
- Anillo de foco único; orden de foco = orden visual (LabBar → A → B → D).
- Estado nunca solo por color (validación con texto; "sin guardar" con marca; referencia rota con
  etiqueta además de tono).
- Áreas de toque adecuadas (Android); overlays descartables; contraste reservado; esquema con nivel de
  expansión expuesto.

## Comportamiento con teclado
- Command Palette (Shell) para comandos e ir a una carta/recurso por ID.
- Fichero: guardar / guardar como / nuevo / duplicar por atajo.
- Edición: deshacer / rehacer; copiar / pegar / duplicar / eliminar parte; mover ataque/habilidad ↑/↓;
  expandir/colapsar secciones (←/→).
- `Esc` cierra overlays / cancela edición. Acciones por teclado **no se animan** (Motion canon).

## Reglas de composición
- El editor **modifica solo datos del recurso Card**; el renderer oficial (compartido) pinta el Preview
  (Regla de Oro).
- Referencias a efectos/animaciones/sonidos = **IDs**; fijar referencia = **selector compuesto**
  (`Popover`+`SearchField`+`ListView`), nunca copia.
- La estructura de la carta se representa como **esquema jerárquico** (Tree), no como grafo.
- Cada región consume su ComponentStyle; ninguna lee Visual Tokens directamente.
- Reordenar = `DropTargetStyle`; comparar = división de `PreviewStyle`. Composiciones, no componentes
  nuevos.

## Restricciones
- Sin explorador de archivos: se abre por **Recurso/ID** (Especialización §2).
- No modifica animaciones, efectos, sonidos, partículas, layouts, renderer ni motor: solo referencias.
- No valida "a su manera": usa las **reglas del núcleo compartido**.
- Sin componentes/tokens/principios/estilos/sistemas nuevos.

## Cierre
**Iteración 11.6 — CERRADA.** El Card Editor puede implementarse **íntegramente** con el Design System
existente.

### Consolidación del modelo de recursos únicos con ID estable
Con cinco Labs, el Studio consolida un **modelo uniforme basado en recursos únicos de ID estable**:
- Cada dominio tiene su par **biblioteca → editor**: animaciones (11.2/11.3), efectos (11.4, editor con
  su propia galería implícita) y cartas (11.5/11.6).
- Una **carta** referencia efectos, animaciones y sonidos **por ID**; **nunca** los copia. Editar un
  efecto o una animación en su Lab actualiza a **todas** las cartas que lo referencian (fuente única).
- Todos los Labs comparten **un único motor, un único renderer y una única fuente de verdad**: el Card
  Editor edita datos de la carta; el motor/renderer del núcleo los ejecuta y pinta; la Card Gallery los
  descubre.
Este grafo de referencias por ID —sin duplicación— es exactamente lo que permitirá al **Combat Lab
(11.7)** ensamblar cartas reales (con sus efectos y animaciones asociados por ID) y ejecutarlas con el
motor real, cerrando el ecosistema sin romper la Regla de Oro. Y, una vez más, todo se ensambla **sin un
solo componente, token o principio nuevo**, confirmando la suficiencia del Design System.
