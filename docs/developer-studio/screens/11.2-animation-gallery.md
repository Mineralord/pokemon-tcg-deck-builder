# 11.2 — Lab: Galería de Animaciones

**Iteración 11.2 de la Fase 11.** Arquitectura funcional del Lab **más importante** del Studio: la
biblioteca definitiva de todas las animaciones del Pokémon TCG Clone. Se monta en el **host del
Workspace (R3)** del Shell (11.1) reconfigurando las zonas canónicas. Ensamblada EXCLUSIVAMENTE con
ComponentStyle existentes. Cadena congelada `Component → ComponentStyle → Visual Tokens → Theme`.

> **Principio fundamental (Regla de Oro).** La Galería **nunca reproduce una simulación**. La región de
> Preview hospeda el **render real del núcleo compartido** (`core:animation(+compose)`), el mismo que
> ejecuta el juego. Lo que se ve aquí es, byte a byte, lo que verá el jugador. La Galería *no* es un
> componente de UI que "dibuja animaciones": es el contenedor que *monta el renderer del juego*.

> **Requisito conceptual (identidad).** Cada animación tiene un **ID estable** y **metadatos
> completos**, independientes de dónde se use. Ese ID la hace direccionable y permite navegar desde una
> animación a todas las cartas, efectos y secuencias que la referencian. La Galería es una **base de
> conocimiento**, no solo un reproductor.

---

## Finalidad
Encontrar **cualquier** animación del proyecto en segundos —aunque existan decenas de miles— y poder
reproducirla, inspeccionarla, compararla, validarla y rastrear todas sus referencias, con el motor real
del juego. Diseñada para crecer durante décadas sin rediseño.

## Responsabilidades
- Indexar y **explorar** el catálogo completo por múltiples ejes (categorías, etiquetas, búsqueda).
- **Reproducir** con transporte completo (play/pausa/reinicio/continua/velocidad/fotograma) usando el
  render del núcleo.
- **Inspeccionar** identidad, propiedades, dependencias, recursos, referencias cruzadas y validación.
- **Comparar** dos o más animaciones lado a lado.
- Mantenerse **utilizable a escala** (virtualización, facetas, búsqueda instantánea, direccionamiento
  por ID).

## Layout (regiones del Lab dentro de R3)
```
┌──────────────────────────────────────────────────────────────────────┐
│ LabBar (Toolbar): vista ▮▤▥ · orden · reproducir todo · sel. acciones │
├───────────────┬───────────────────────────────────┬──────────────────┤
│ A · Navegador │ B · Preview grande (render real)   │ D · Inspector    │
│   facetado    │   [ transporte: ◄ ❚❚ ► ↺ x1.0 ]   │  Identidad (ID)  │
│  (Biblioteca) │   (modo comparación: B se divide)  │  Propiedades     │
│  búsqueda     │                                    │  Dependencias    │
│  categorías   ├───────────────────────────────────┤  Recursos        │
│  etiquetas    │ C · Timeline (scrub / fotograma)   │  Usos (cartas)   │
│  catálogo     │                                    │  Usos (efectos)  │
│  (grid/lista) │                                    │  Refs cruzadas   │
│               │                                    │  Validación      │
├───────────────┴───────────────────────────────────┴──────────────────┤
│ (Status Bar del Shell: estado de compilación · validación · progreso) │
└──────────────────────────────────────────────────────────────────────┘
```
Splitters redimensionables entre A/B/D y B/C: `DividerStyle` + `ResizeHandleStyle` (como en el Shell).

## Regiones y composición (todo con ComponentStyle existentes)
- **LabBar** — `ToolbarStyle`. Conmutador de vista (`SegmentedButtonStyle`: cuadrícula/lista/compacta/
  detallada), orden (`MenuStyle`/`ButtonStyle`), reproducir-todo y velocidad global (`IconButtonStyle`
  + `SliderStyle`/`SegmentedButtonStyle`), acciones de selección múltiple (`ButtonStyle`), y estado de
  selección (`BadgeStyle`).
- **A · Navegador facetado (Biblioteca, Z3)** — `PanelStyle` que aloja:
  - Búsqueda instantánea: `SearchFieldStyle`.
  - Colecciones (Favoritos / Recientes / Historial): `TabStyle` + `ListViewStyle`/`ListRowStyle`.
  - Categorías jerárquicas: `TreeStyle`/`TreeRowStyle`.
  - Etiquetas y filtros: `ChipStyle` (multi-selección) + `CheckboxStyle` en un `PopoverStyle`/`MenuStyle`.
  - **Catálogo** en cuatro vistas (misma data, distinto *layout*, no distinto componente):
    - *Cuadrícula*: mosaico de celdas = `PanelStyle` (miniatura con render real + `BadgeStyle` de estado
      + `IconButtonStyle` favorito) dentro de `ScrollAreaStyle` (virtualizado).
    - *Lista* / *Compacta*: `ListViewStyle`/`ListRowStyle` (densidad `Default`/`Compact`).
    - *Detallada*: `TableStyle` con columnas ordenables (`TableStyle.sortIndicator`).
  - Selección múltiple: estado `Selected` de `DataRowStyle` + `CheckboxStyle`.
- **B · Preview grande (Z6)** — `PreviewStyle` (telón acromático) que **monta el renderer del núcleo**;
  transporte en `PreviewOverlayStyle` (controles `IconButtonStyle`: ◄ fotograma, ❚❚ pausa, ► play, ↺
  reinicio, continua; velocidad `SegmentedButtonStyle`/`SliderStyle`). **Comparación (Benchmark Z10):**
  B entra en "modo comparación" dividiéndose en 2+ `PreviewStyle` con `DividerStyle`; `SelectionFrameStyle`
  marca el activo.
- **C · Timeline (Z9)** — `TimelineStyle` + `TimelineTrackStyle` + `TimelineMarkerStyle` +
  `TimelineSelectionStyle`: scrub, marcadores de keyframe, avance fotograma a fotograma, rango.
- **D · Inspector (Z7)** — `InspectorSectionStyle` + `PropertyGroupStyle` + `PropertyRowStyle`:
  - *Identidad*: **ID estable** (`Numeric`/`Mono`), nombre, metadatos (`PropertyRow`), etiquetas
    (`ChipStyle`), favorito (`ToggleButton`/`IconButton`).
  - *Propiedades*: duración, curvas, capas… (`PropertyRow`, valores `Numeric`).
  - *Dependencias* y *Recursos utilizados*: `TreeStyle`/`ListViewStyle`.
  - *Usos* (cartas / efectos / secuencias que la referencian) y *Referencias cruzadas*: `ListViewStyle`/
    `ListRowStyle` con enlaces `ButtonStyle` `Ghost` que **navegan a otro Lab/recurso** vía el contrato
    del Shell.
  - *Validación*: estado de compilación, advertencias y errores con `BadgeStyle.Tone` + `PropertyRow`
    en estado `Error`.

## Jerarquía visual
Preview (protagonista, contenido) › Catálogo/Navegador (encontrar) › Inspector (mando) › Timeline
(tiempo) › LabBar/Status (control/residual). El chasis reposa; solo selección/foco/alerta suben (VG-K).

## Flujo principal
1. Entrar al Lab (por defecto del Studio) → catálogo virtualizado + Preview vacío (`EmptyStateStyle`).
2. **Encontrar** por cualquier eje combinable: teclear en búsqueda, acotar por categoría (Tree),
   filtrar por etiquetas (Chips), o saltar por **ID** desde el Command Palette del Shell.
3. Seleccionar una animación → B monta el render real y auto-reproduce; D carga identidad/propiedades;
   C carga su línea de tiempo.
4. **Reproducir/inspeccionar:** transporte en B, scrub/fotograma en C, ajustes/lectura en D.
5. **Rastrear conocimiento:** desde D → *Usos*/*Referencias cruzadas* → abrir la carta/efecto que la usa
   (navegación entre Labs).

## Flujo secundario
- **Comparar:** seleccionar 2+ (selección múltiple) → "modo comparación" divide B; transporte
  sincronizado o independiente.
- **Curar:** marcar favoritos, revisar recientes/historial, reordenar.
- **Validar en lote:** selección múltiple → acción de validación; resultados por `BadgeStyle`/`Toast`.

## Navegación
- **Primaria** del Lab: el Navegador facetado (A) — buscar/filtrar/categorizar.
- **Direccionamiento estable:** por ID vía Command Palette (Shell).
- **Cruzada:** enlaces del Inspector hacia cartas/efectos (contrato del Shell; no rompe el Shell).
- Dentro del Lab, un recurso "abierto" por foco; comparación admite varios simultáneos en B.

## Estados
- **rest/hover/pressed/selected:** celdas/filas (`DataRowStyle`), controles.
- **focus:** anillo único.
- **loading:** catálogo con `SkeletonStyle`; Preview con `BusyOverlayStyle` mientras el núcleo prepara
  el render; operaciones largas (validar lote) con `ProgressOverlayStyle` + segmento de Status Bar.
- **empty:** sin resultados de búsqueda / sin selección → `EmptyStateStyle` (con "Limpiar filtros").
- **error:** recurso inexistente → `EmptyStateStyle` error + `ToastStyle`; validación con advertencias/
  errores → `BadgeStyle.Tone` + `PropertyRow` Error; fallo crítico de render → nivel del Shell.
- **validación/compilación:** `BadgeStyle` (Success/Warning/Danger) en celda, Inspector y Status Bar.

## Organización de la información a escala (decenas de miles, décadas)
- **Ejes combinables** (facetado): categorías jerárquicas (Tree) × etiquetas (Chips multi) × búsqueda
  instantánea (SearchField) × colecciones (Favoritos/Recientes/Historial).
- **Direccionamiento por ID estable:** cualquier animación es alcanzable directamente por ID (Command
  Palette), sin depender de navegar.
- **Ordenación** por columnas en vista detallada (Table).
- **Virtualización:** `ScrollAreaStyle` renderiza solo lo visible (comportamiento, no componente).
- **Divulgación progresiva:** vista compacta por defecto; detalle al seleccionar (Preview + Inspector).
- **Densidad** `Default`/`Compact` para maximizar elementos por pantalla sin perder legibilidad.

## Accesibilidad
- Anillo de foco único; orden de foco = orden visual (LabBar → A → B → C → D).
- Estado nunca solo por color (validación con icono/texto además de tono; selección con marcador).
- Áreas de toque adecuadas (Android); overlays descartables; contraste reservado.
- Miniaturas con nombre/ID textual (no dependen solo de la imagen).

## Comportamiento con teclado
- Command Palette (Shell) para saltar por nombre/ID e invocar comandos del Lab.
- Búsqueda con foco directo; `Esc` limpia filtros.
- Catálogo: `↑↓←→` navegan grid/lista; `Enter` selecciona/reproduce; `Space` play/pausa;
  `Shift/Ctrl`+selección para múltiple; `F2` no aplica (la Galería no renombra: eso es del editor).
- Transporte: `Space` play/pausa; `,`/`.` fotograma anterior/siguiente; `←/→` scrub; velocidad por
  atajo; `Home` reinicia.
- Acciones iniciadas por teclado **no se animan** (Motion canon).

## Reglas de composición
- El Lab **monta el renderer del núcleo** en la región `PreviewStyle`; no reimplementa animación (Regla
  de Oro). El renderer es el módulo compartido, no un ComponentStyle.
- Cada región consume su ComponentStyle; ninguna lee Visual Tokens directamente.
- Las cuatro "vistas" son **layouts** de los mismos datos sobre componentes existentes; no son
  componentes distintos.
- La miniatura/celda y la comparación son **composiciones** (Panel/Preview + controles), no componentes
  nuevos.
- Navegación cruzada mediante el **contrato del host** del Shell; el Lab no altera el Shell.

## Restricciones
- Sin explorador de archivos: se navega por **Recursos** (animaciones), no por carpetas
  (Especialización §2).
- La Galería **explora/reproduce/inspecciona/compara/valida**; **editar** la animación es competencia
  del editor correspondiente (otro Lab), alcanzable por referencia cruzada.
- Sin componentes/tokens/principios/estilos/reglas/sistemas nuevos.

## Cierre
**Iteración 11.2 — CERRADA.** La Galería de Animaciones puede **escalar indefinidamente** usando solo el
Design System existente: crece en *datos* (más animaciones, más etiquetas, más referencias), no en
*componentes*. La organización facetada + ID estable + virtualización sostiene decenas de miles de
elementos sin nuevos widgets.

### Por qué valida definitivamente la suficiencia del Design System
La Galería es la herramienta **más compleja y densa** del Studio —navegación facetada, catálogo masivo
virtualizado, cuatro vistas, transporte multimedia, timeline por fotograma, comparación multi-panel,
inspector con base de conocimiento de referencias cruzadas y validación— y aun así se ensambla **por
completo** con los ComponentStyle de la Fase 10, montando el **renderer real del juego** en la región de
Preview. Si el Design System basta para esto, basta para cualquier otro Lab del Studio (todos más
simples): editores, sandbox, build. Queda demostrado que el PDS es **completo y autosuficiente** para
construir herramientas complejas sin excepciones ni componentes nuevos.
